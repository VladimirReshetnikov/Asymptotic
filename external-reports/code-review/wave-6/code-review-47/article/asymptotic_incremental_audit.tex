\begin{abstract}
This report examines a pinned revision of the Asymptotic repository while excluding the substantial existing review backlog from its new finding count. The most significant additional implementation mechanism identified is duplicated work in the mutually recursive Mathics realness and sign provers. A nested expression containing only 37 leaves induces 335,521 helper-body evaluations in a source-faithful model at the existing depth limit of 24. Query-local memoization reduces that model to 200 distinct body evaluations without changing its inconclusive answer. An exact recurrence explains both the initial exponential growth and the fixed-depth plateau; executions of the retrieved helpers in Wolfram 15.0.0 confirm the initial sequence through nesting depth six.

Two independently reproduced defects concern the mathematical documentation gate. Five production checks use Python assertions, so optimized execution can accept deliberately invalid fixtures and still report zero missing references or citations. Separately, regular-expression extraction treats commented-out TeX definitions as active labels and bibliography entries. This masks genuine undefined references even in ordinary Python execution. It also creates false duplicate-label alarms and attempts to read commented-out inputs. Real LaTeX runs distinguish these cases from valid documents.

The report gives concrete witnesses, severity and reachability boundaries, mathematical derivations, candidate Python repairs, portable reproduction specifications, and focused acceptance criteria. It does not claim a newly demonstrated incorrect asymptotic formula, universal Wolfram/Mathics equivalence, or an integrated production fix. Novelty screening used the maintained all-wave registers and indexes, with targeted inspection of nearby findings and the fifth-wave documentation review; it was not a fresh cover-to-cover rereading of every retained article.
\end{abstract}

\section{N01: duplicated Mathics proof search}
\subsection{The exact source mechanism}

\code{MathicsAssumptions.wl} contains two mutually recursive bounded procedures: \code{mathicsRealProof} and \code{mathicsSignProof}. They receive an expression, retained facts, and a depth budget. Their return values distinguish proved information from an inconclusive \code{None}. The simplification adapter uses these procedures before or around native Mathics simplification.\cite{mathicsass,mathicssimp}

The problematic interaction is specific. To establish the realness of a power, the realness prover first verifies the exponent, then asks for signs of the base, and may later ask for realness of the same base. To establish the sign of \code{Cosh[z]}, the sign prover asks whether \code{z} is real. When that is not proved, it eventually falls back to asking whether the complete \code{Cosh[z]} is real. The latter query asks for realness of \code{z} again, at another depth. Nested powers and hyperbolic cosines multiply these repeated subqueries.

The depth counter prevents this particular recursion from being infinite, but does not prevent extensive duplicated work. In the relevant pure fragment, every recursive edge decreases depth. The implementation nevertheless traverses a tree of calls instead of sharing the repeated nodes of that finite dependency graph.

\subsection{A compact witness family}

Let $a$ be an unassigned symbolic parameter, with no realness or sign facts, and define
\begin{equation}
 E_0=a,\qquad E_{n+1}=\cosh(E_n)^2.
 \label{eq:family}
\end{equation}
The corresponding Wolfram construction is
\begin{lstlisting}
Nest[Cosh[#]^2 &, a, n]
\end{lstlisting}

Its native leaf count is $1+3n$: each stage adds the heads \code{Cosh} and \code{Power}, and the exponent 2. At $n=12$ this is only 37 leaves. The correct conclusion of the restricted proof procedure with empty facts is inconclusive. This witness does not assert that the expression is nonreal; it demonstrates excessive work before returning the same lack of proof.

The direct helper query is
\begin{lstlisting}
AsymptoticAnalysis`Mathics`mathicsRealProof[
  Nest[Cosh[#]^2 &, a, n], {{}, {}}, 24]
\end{lstlisting}

A prospective public Mathics stress case is a package-only expansion with such a fixed coefficient, for example $E_n+x$, without a realness assumption on $a$. This is a \emph{reachability and timing specification}, not an observed public Mathics result. Earlier normalization and Mathics-specific evaluation may change the precise public call count. With $a\in\mathbb R$, the same family supplies successful realness controls and must not be penalized or misclassified by the repair.

\subsection{An exact call-count recurrence}

Count entries into the bodies of the two proof helpers, but not the fact lookup, numeric predicates, expression evaluation, or other primitive work within each body. Write $R_n(d)$ for the total count of a realness query for $E_n$ with depth $d$ and empty facts.

\begin{proposition}[Restricted-family recurrence]
For the source branches exercised by \eqref{eq:family},
\begin{align}
 R_0(d)&=1,\qquad R_n(d)=1\quad(d\leq0),\\
 R_n(1)&=2,\qquad R_n(2)=7\quad(n\geq1),\\
 R_n(d)&=5+2R_{n-1}(d-2)+R_{n-1}(d-3)
 \quad(n\geq1,\ d\geq3).
 \label{eq:recurrence}
\end{align}
\end{proposition}

\begin{proof}
The symbolic base case has no applicable realness rule and makes no recursive real/sign call. A nonpositive depth returns immediately after the counted entry. At depth one, the power's realness body and its exhausted exponent-realness query contribute two entries. At depth two, the exponent is established, the sign query for the cosine makes three entries, and the later realness query for that cosine makes two, for a total of seven.

For $d\geq3$, the power's realness entry and the realness check of its numeric exponent contribute two. Its sign query for $\cosh(E_{n-1})$ contributes its own entry, a query for $E_{n-1}$ at depth $d-2$, and the realness fallback on that cosine. That fallback contributes one entry and a query for $E_{n-1}$ at depth $d-3$. Finally, the integer-power branch independently queries the realness of the cosine: one entry plus another query for $E_{n-1}$ at depth $d-2$. Summing yields \eqref{eq:recurrence}. Every relevant realness subquery remains inconclusive for the empty-fact symbolic family, so none of these branches is skipped by a successful proof.
\end{proof}

\begin{corollary}[Initial growth]
Whenever $d\geq3n$,
\begin{equation}
 R_n(d)=\frac{7\cdot3^n-5}{2}.
 \label{eq:initial-growth}
\end{equation}
\end{corollary}
\begin{proof}
At that depth, the recurrence never encounters a truncated power query. Its three recursive subqueries therefore have the same untruncated count. Starting with $R_0=1$, solve $R_n=3R_{n-1}+5$.
\end{proof}

This is not a claim of exponential growth for arbitrarily large $n$ while $d$ stays fixed. For fixed $d$, the family saturates once $n\geq\lceil d/2\rceil$. Let $C(d)$ denote that plateau. It obeys
\[
 C(0)=1,\quad C(1)=2,\quad C(2)=7,\qquad
 C(d)=5+2C(d-2)+C(d-3).
\]
Writing $F_0=0,F_1=1$ for the Fibonacci numbers gives the exact expression
\begin{equation}
 C(d)=4F_d+2F_{d+1}+\frac32(-1)^d-\frac52.
 \label{eq:fibonacci}
\end{equation}
It follows either by substitution and the three initial values, or from the homogeneous characteristic polynomial $(\lambda+1)(\lambda^2-\lambda-1)$. Thus the depth-limited plateau itself grows exponentially with the permitted depth. In particular, $C(24)=335{,}521$.

\subsection{A repair with a precise equivalence obligation}

The appropriate local repair is to evaluate each pure proof subquery at most once per request. Its identity must include the operation (realness or signs), the normalized expression, the retained facts or an immutable identity for them, and the remaining depth. An inconclusive answer is cacheable for that exact key. It must not be confused with a proved falsehood.

Depth is essential. A shallow query about a known-real expression can return \code{None} while the deeper query proves it real. Facts are essential for the analogous distinction between unassigned $a$ and $a\in\mathbb R$. A global memo table keyed only by expression would change the reasoning contract and risk stale assumptions.

For a pure, stable expression/fact snapshot, correctness follows by induction on remaining depth. A first visit evaluates the original body and stores its answer. Every recursive dependency has smaller depth, so already stored dependencies agree with the original procedure by induction. A repeated visit returns the identical stored answer. This proves preservation of the procedure's answers, not completeness of its mathematical reasoning.

A request-local memoized graph has at most one body evaluation per reachable key. With $O(n)$ distinct subexpressions and depth budget $D$, the number of candidate keys is $O(nD)$ for this family and one fixed fact set. That bound concerns graph nodes; it does not assume constant-time hashing or matching of large symbolic expressions. The supplied \code{proof_cost_model.py} demonstrates the scheduling change on an immutable restricted grammar and tests assumption isolation, depth-sensitive keys, successful realness controls, and explicit model-budget exhaustion.

The model is intentionally not offered as a complete replacement for \code{MathicsAssumptions.wl}. Production integration must decide how to scope the memo table, how to preserve existing evaluation semantics for user-defined or effectful expressions, and how interrupted requests release local state. Sharing is immediately justified for the pure built-in fragment of the witness; broader input classes require their own preservation tests. No global System definitions should be changed for this repair.

\subsection{Focused acceptance criteria}

The first production check should execute the direct helper family in both supported interpreters and both package layouts, recording answers and helper-body counts separately from elapsed time. The existing small-depth sequence supplies an exact baseline. A memoized implementation should preserve all answers while making repeated visits cache hits rather than full body evaluations.

Successful controls should include retained realness facts, positive bases, and different depth budgets in the same request. A fresh request with changed assumptions must not reuse the old answer. An interrupted computation must not retain a half-populated cross-request cache. These are specific acceptance obligations of the proposed fix, not a new general caching architecture.

Finally, run the proposed coefficient-containing public expression in Mathics with and without a realness assumption. Record which public path reaches the helper, what preprocessing changes the expression, and whether the eventual result is an expansion, a justified refusal, or a timeout. That end-to-end characterization remains outstanding; a smaller helper count alone must not be advertised as a package-wide acceleration.

\section{N02: documentation checks disappear under optimization}
\subsection{Five assertions implement production validity gates}

The complete retrieved \code{validation/check_documentation.py} contains five \code{assert} statements. Four check label uniqueness, resolution of mathematical references, presence of bibliography entries, and separation of software content from the mathematical article. The fifth checks archive equality inside a loop over six preserved engineering files. Afterward, the function unconditionally reports \code{"MissingReferences": 0} and \code{"MissingCitations": 0}.\cite{doccheck}

Python's \code{-O} mode removes assertion statements; \code{-OO} also removes docstrings. The environment variable \code{PYTHONOPTIMIZE} can select corresponding optimization behavior. These are interpreter semantics, not a speculative optimization by a downstream compiler.\cite{pythonopt,pythonassert}

Consequently, an optimized invocation can skip precisely the predicates that would justify those clean report fields. Other checks remain active: the guide builder, link checker, encoding checker, reads, and Git subprocess calls are not removed merely because this module uses assertions. The finding is a selective gate bypass, not a claim that every possible error becomes invisible.

\subsection{Controlled execution of the actual checker}

The bundle contains a verbatim copy of the retrieved upstream file. Its reconstructed Git blob identity was checked against the connector's returned blob identity during preparation; it is not a rewritten model of the checker. Each fixture supplies a small mathematical document and six archive files, while unrelated dependency providers return explicit fixture records.

The following results summarize the decisive cases:

These observations do not allege that a published historical receipt was created under optimization or that the current article has a broken reference. They demonstrate that the current validity predicate depends on a process-startup mode that the function does not reject or accommodate. The ordinary negative controls verify that the same fixtures are meaningful in nonoptimized execution.

\subsection{The candidate fix}

A validation condition should use an ordinary branch and explicit exception, not a removable assertion statement. The small supplied helper is:
\begin{lstlisting}[language=Python]
def require(condition: bool, message: str) -> None:
    if not condition:
        raise AssertionError(message)
\end{lstlisting}

Raising \code{AssertionError} explicitly preserves the existing ordinary failure class; optimization does not remove an explicit \code{raise}. This is intentionally different from replacing the predicate with another \code{assert}. The emitted candidate changes all five statements to \code{require(...)} calls and leaves the successful receipt schema and the archive CRLF normalization policy unchanged.

The patch generator refuses unexpected source anchors or an unexpected assertion count and never overwrites its input file. It is targeted to this pinned file shape, not a general source transformation tool. The supplied unified patch also adds the helper module to \code{validation}, so the new import has a concrete destination.

A narrower alternative is to refuse optimized execution at startup. That would prevent false success, but would make an otherwise valid validation command unavailable in that mode. Explicit checks avoid the needless restriction and make the function correct when imported as well as when run as a script.

\subsection{Acceptance and remaining scope}

Normal and optimized execution should agree on the acceptance decision for each tested fixture. The real guide/link/encoding/Git integrations must then be rerun in the repository, because deterministic substitutes cannot validate those dependencies. The unchanged success path and accepted CRLF-normalized archive control are important: a fix that simply refuses every run would satisfy the negative witnesses but be useless.

The bundle separately verifies the explicit \code{require} helper under normal, \code{-O}, and \code{-OO} execution. The full 56-observation checker matrix uses ordinary and \code{-O} execution; it is not mislabeled as a three-mode full matrix. No recommendation is made to eliminate all debugging assertions from unrelated code. The repair applies to these production acceptance predicates.

\section{N03: comments alter mathematical cross-reference validity}
\subsection{Source text is not the same as active TeX}

The checker discovers immediate \code{\input} files and then extracts \code{\label}, \code{\ref}, \code{\eqref}, \code{\pageref}, \code{\bibitem}, and \code{\cite} using regular expressions over unfiltered source text. It does not distinguish an ordinary TeX line comment from an active command.\cite{doccheck}

This defect is independent of N02. It occurs with assertions fully enabled, and merely replacing \code{assert} statements leaves it present.

A minimal masking witness is:
\begin{lstlisting}
See \ref{ghost}.
% \label{ghost}
\end{lstlisting}

The original checker counts one label and one reference, sees no missing key, and returns a clean result. Real LaTeX ignores the commented-out definition and reports \code{Reference `ghost' ... undefined}. Replacing the reference with \code{\cite{ghost}} and the comment with a commented-out \code{\bibitem{ghost}} gives the analogous false acceptance for a citation.

The opposite problem also occurs. A valid active label followed by a commented-out copy is counted twice, causing a false duplicate-label rejection. A commented \code{\input{does-not-exist}} is treated as a dependency and produces \code{FileNotFoundError}, although the compiler never attempts to load it.

\subsection{Compiler cross-checks}

Five actual small documents were compiled twice with \code{pdflatex}. The second-pass logs distinguish the cases without relying on a stale first-pass cross-reference state:

These are synthetic documents. The review does not claim that the pinned mathematical article currently contains one of these mistakes. The demonstrated defect is in how the validation tool decides and reports correctness.

\subsection{A narrow lexical repair}

The candidate masks ordinary percent comments before discovering inputs and extracting mathematical keys. It preserves line boundaries and keeps original source bytes available for encoding, archive, and separation checks. Percent signs preceded by an odd run of backslashes are treated as escaped; an even run permits a comment to begin under standard TeX catcodes.

Preserving token boundaries is important. Blindly deleting a comment and its newline can accidentally concatenate fragments in a character-level scanner. The supplied masker replaces comment characters by spaces while retaining line endings. A test ensures that a fragment such as \code{\la}, a comment, and later \code{bel} does not become a newly invented \code{\label} token.

The extraction changes are deliberately local. Immediate input discovery uses the masked master. After the existing one-level concatenation, label/reference/citation extraction uses a masked copy. Archive comparisons still use unmodified bytes. The existing software-separation policy still examines raw text, so this change does not silently decide that software material in comments is permitted.

The implementation is not a complete TeX parser. It does not implement arbitrary catcode changes, \code{\verb}, verbatim environments, macro-generated labels, or unrestricted recursive input expansion. Such features require a declared parsing policy or a compiler-derived check. The ordinary comment witnesses are already sufficient to establish the bug; claiming a universal parser would exceed both the patch and the evidence.

\subsection{A useful next development step}

The focused invariant is that inserting or deleting genuinely inactive ordinary comments must not change mathematical cross-reference validity. The new fixtures test that invariant in both directions: comments must neither manufacture a definition nor create a duplicate or dependency.

After the narrow repair, the maintainers can define the admitted source grammar explicitly and decide how unsupported TeX constructs are handled. For syntax beyond that grammar, comparison against cross-reference information produced by the same actual compiler run is more reliable than treating every command-shaped substring as active source. Such reconciliation should identify unresolved keys and compiler warnings, not merely rely on a zero process exit status.

This is an extension of the mathematical-reference validity check, not another proposal about build-recorder provenance or publication transactions. It should be accepted separately from N02: an optimization-invariant but comment-blind checker is still wrong, and a comment-aware checker whose validity predicates disappear is still wrong.

\section{Prioritized, finding-specific development plan}

The two documentation fixes are small enough to review together but should retain separate tests and disposition records. First make acceptance predicates optimization-invariant. Then make ordinary comments invisible to mathematical-key extraction and dependency discovery. Preserve positive controls and raw-source policies. This closes two independent ways that a clean-looking receipt can be unsupported by its actual predicates.

For N01, first reproduce the helper counts in Mathics rather than guessing at an elapsed-time improvement. Then implement request-local sharing for a pure admitted fragment, using keys that retain operation, expression, facts, and depth. Check equivalent answers before measuring runtime. Only then broaden the sharing scope, after examining evaluation effects and backend expression canonicalization.

The final acceptance record should be specific: which checker modes, which comment grammar, which helper family, which runtime, and which public path were actually exercised. The existing review registers already cover wider architectural and coverage goals. They need not be reintroduced as newly discovered recommendations in order to integrate these three deltas.

\section{Conclusion}

This review's strongest new result is an explicit account of how a small nested coefficient can cause extensive repeated work in the Mathics proof program. The exact recurrence, the native-host source-helper observations, and the independently checked memoizing model agree on the relevant mechanism. The default depth cap makes the recursion finite, but does not make its duplicated work small.

The documentation findings are more directly executable: the actual checker accepts constructed invalid inputs when assertions are optimized away, and it accepts undefined TeX references when their only apparent definitions are comments. The supplied candidate addresses those two mechanisms and passes the focused bundle tests, with compiler controls confirming the lexical distinction.

No new incorrect asymptotic formula is claimed. Seven selected native package controls succeeded; broad mathematical and cross-interpreter correctness remains a separate qualification task. The practical output of this audit is three scoped findings with explicit evidence, two runnable tooling repairs, a proof-search scheduling prototype, and reproducible acceptance criteria rather than another restatement of the existing backlog.
