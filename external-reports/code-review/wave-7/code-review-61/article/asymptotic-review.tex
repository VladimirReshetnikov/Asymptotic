\begin{abstract}
This review examines the pinned Asymptotic repository against the substantial existing review corpus rather than producing another inventory of already reported problems. The principal new result is a concrete failure of \code{inverseFunctionConditionOnJet}: the \code{Element[..., Reals]} branch tests the retained coefficients of a truncated jet but does not require its remainder to vanish. A cancelled exponential Taylor tail therefore supplies a family of false realness proofs. The public \code{SeriesObservable} call then returns \code{1} with zero remainder and \code{Exact -> True}, although the conditional expression has no germ on the requested positive approach. Five low-cutoff failures and five higher-cutoff refusals were observed on Wolfram Language 15.0.0. A one-line exactness guard rejects the five low-cutoff cases in focused checks while retaining exact polynomial and exact-zero controls. The article also derives a Hermitian half-spectrum implementation for real Fourier-polynomial coefficients, including multiplication, Euler differentiation, the existing inverse-coefficient recurrence, precise operation counts, budget compatibility, and a tested exact Python prototype over \(\QQ(\sqrt2)[\ii]\). Twelve independent Python test methods pass. The report distinguishes observed behavior, mathematical proofs, source-level compatibility analysis, and unexecuted integration work throughout.
\end{abstract}

\section{Assessment, scope, and exclusion of earlier findings}
\subsection{What this review establishes}
The most important repair identified here is small: an asymptotic approximation must not be used as an exact membership predicate merely because all its displayed coefficients are real. This is not a dispute about the sharpness of a remainder. It is a successful public result for an expression whose stated condition is false everywhere on the approach. The affected path is in the condition checker, before the observable body is constructed. Its body can be the constant \code{1}; no difficult inverse, special function, branch point, or approximate arithmetic is needed.\cite{expressions,operations}

The distinction between the two contributions in this article is essential. \textbf{N01 is a correctness defect with a reproduced public witness. H01 is a concrete implementation proposal with independent algebraic validation, not a measured defect or a claimed native speedup.} They have different acceptance criteria and should not be merged into one numerical ``issues found'' score.

\section{The representation boundary that matters}
\subsection{A jet is not the function it approximates}
The ordinary internal jet has the form
\begin{equation}\label{eq:jet}
 J=(T,P,D),\qquad
 T=\{(\beta_j,Q_j)\}_{j=1}^{m},
\end{equation}
with the intended meaning, for a positive local coordinate \(w\to0^+\),
\begin{equation}\label{eq:meaning}
 f(w)=\sum_j w^{\beta_j}Q_j(\log w)
       +\OO\!\left(w^P(1+|\log w|)^D\right).
\end{equation}
The rows retain an ordered finite set of weights and polynomial logarithmic coefficients. \code{P === Infinity} is the ordinary exact-jet convention; a finite \(P\) retains an unknown tail. The surrounding series representation can also carry an exact offset and prefactor, so the finite jet is only one part of the public object.\cite{core,operations}

Several elementary implications follow directly from this meaning. An empty row list with finite \(P\) is a pure remainder, not exact zero. A real polynomial in the row list describes the finite approximation, not automatically the entire remainder class. An expression's numerical smallness says nothing by itself about exact membership in \(\RR\), the integers, or an algebraic variety.\cite{element} In particular,
\begin{equation}\label{eq:imaginary}
 0\quad\hbox{and}\quad \ii w^P
\end{equation}
share the same zero jet modulo \(\OO(w^P)\), but only the first is real for positive \(w\).

The package's arithmetic can correctly preserve an error bound and still be misused by a caller that reads only \code{j[[1]]}. N01 is precisely such a caller: it asks the jet algebra for an approximation to the \emph{argument of a predicate}, then treats the coefficient list as a proof of the predicate itself.

\subsection{The public path}
The ordinary \code{SeriesObservable} route first acquires and flattens a series representation. It resolves an operation cutoff, peels a surrounding \code{ConditionalExpression}, asks \code{inverseFunctionConditionOnJet} whether the condition is established, and only then applies \code{seriesJetApply} to the observable body. The result is built by \code{seriesMake}.\cite{operations,expressions}

For the witness in the next section, the observable body is exactly \code{1}. Once admission succeeds, constructing this body is trivial and legitimately yields an exact constant \emph{as an algebraic body}. Final real-coefficient checks on that constant cannot recover the condition that was wrongly admitted. This explains why the resulting object can look exceptionally clean: its finite expression is real, its error is zero, and its exactness flag is true. The corruption occurred in the logical gate, not in the final constant's arithmetic.

Wolfram's documented \code{ConditionalExpression[expr,cond]} denotes \code{expr} when the condition holds; a false condition evaluates to \code{Undefined}. Thus removing an everywhere-false condition is not an innocuous simplification of presentation. It changes an undefined conditional expression into an ordinary value.\cite{conditional}

\subsection{Why the cutoff enters the logical decision}
The same requested cutoff \(h\) used for an observable calculation is passed to the condition-on-jet routine. This can be appropriate for a \emph{sufficient} asymptotic sign proof: a retained positive leading term may dominate a controlled smaller remainder. It is not sufficient for exact realness merely to fail to see a nonreal term below \(h\).

A useful distinction is between a proof being unavailable at low precision and a proof being false. A low-precision checker may return ``not proved'' and subsequently establish a condition after refinement. It must not establish a condition at low precision that becomes disproved when one more term is retained. The reproduced cutoff pairs below exhibit exactly that reversal.

\section{N01: false realness proofs from cancelled Taylor tails}
\subsection{A minimal public witness}
Load the pinned package, then evaluate the following with otherwise unassigned symbols. The symbolic parameter \code{a} carries the assumption \code{a == I}; the actual source being expanded is the exact real function \code{x}.
\begin{lstlisting}
s = AsymptoticAnalysis`AsymptoticExpansion[
  x, {x, 0, 3}, Assumptions -> a == I,
  "Backend" -> "Package"];

bad = AsymptoticAnalysis`SeriesObservable[
  s,
  ConditionalExpression[
    1, Element[a (Exp[z] - 1 - z), Reals]],
  z, "Cutoff" -> 2];

{bad["Expression"], bad["Remainder"], bad["Exact"]}
(* {1, 0, True} on the reviewed baseline *)
\end{lstlisting}
The source object has expression \code{x}, remainder zero, and the retained assumption \code{a == I}. This is not a request to expand a complex-valued source. A complex quantity appears in a \emph{condition that should be rejected}; treating it as a proved real quantity is the failure.

Increasing the observable cutoff from 2 to 3 changes the response to
\begin{lstlisting}
Failure["IncompatibleObservableCondition", ...]
\end{lstlisting}
The higher-cutoff refusal is correct. The lower-cutoff success is not a weaker but valid expansion of the same object: the conditional expression has no value on the positive approach at all.

An independent native simplification returned
\begin{lstlisting}
FullSimplify[
  Element[a (Exp[x] - 1 - x), Reals],
  a == I && x > 0]
(* False *)
\end{lstlisting}
This check supports the observation, but the proof does not depend on a simplifier.

\subsection{A counterexample family and its proof}
For a nonnegative integer \(m\), define
\begin{equation}\label{eq:tail}
 T_m(x)=e^x-\sum_{k=0}^{m}\frac{x^k}{k!}.
\end{equation}
Use the condition
\begin{equation}\label{eq:condition}
 C_m(x):\quad aT_m(x)\in\RR,\qquad a=\ii.
\end{equation}

\begin{proposition}\label{prop:false}
For every integer \(m\ge0\), \(C_m(x)\) is false for every real \(x>0\). Therefore the conditional observable equal to 1 only when \(C_m\) holds has no germ on \(x\to0^+\).
\end{proposition}
\begin{proof}
The convergent exponential series gives
\[
 T_m(x)=\sum_{k=m+1}^{\infty}\frac{x^k}{k!}>0
 \qquad(x>0).
\]
Consequently \(\ii T_m(x)\) has zero real part and a strictly positive imaginary part. It is not a real number at any point of the approach. There is no punctured positive interval on which the condition is true.
\end{proof}

The family also exposes exactly why the error is cutoff-sensitive:
\begin{equation}\label{eq:firstnonreal}
 aT_m(x)=\frac{\ii}{(m+1)!}x^{m+1}+\OO(x^{m+2}).
\end{equation}
An exclusive cutoff \(h=m+1\) omits the first nonreal term. The returned approximation to the predicate argument is a pure remainder. At \(h=m+2\), the first nonreal coefficient becomes visible. The observed native behavior was:

\subsection{The source-level cause}
The relevant branch is structurally:
\begin{lstlisting}
If[head === Element && c[[2]] === Reals,
  j = seriesJetApply[c[[1]], x, input, d, cut, limit];
  Return[
    And @@ (
      TrueQ[FullSimplify[
        Element[#[[2]], Reals],
        seriesAss[d] && Element[d["LogVariable"], Reals]
      ]] & /@ j[[1]]),
    Module]];
\end{lstlisting}
Only \code{j[[1]]}, the finite rows, participates in the proof. The finite remainder exponent \code{j[[2]]} is ignored. When the rows are empty, the conjunction is empty and hence true. More generally, a real finite prefix can hide a nonreal tail; emptiness is the simplest manifestation, not the entire issue.\cite{expressions}

The neighboring equality handling demonstrates the missing distinction clearly. When a relational difference has no retained rows, that branch requires \code{j[[2]] === Infinity} before using exact equality or the corresponding non-strict relations. The realness branch has no analogous exactness requirement. This observation identifies a local inconsistency; it does not imply that every other relation is fully audited or that copying one check proves the entire predicate engine correct.\cite{expressions}

\subsection{Why two tempting diagnoses are wrong}
The failure is not that a high-order nonreal monomial is universally dropped. The control \code{Element[a z^2, Reals]}, under \code{a^2 == -1}, was refused at both cutoffs 1 and 3. The exact polynomial path retains the coefficient information needed to reject it. The cancelled exponential tail is significant because the analytic composition introduces finite precision while removing the low-order rows.

Nor is the failure caused by the constant body having an incorrect coefficient. The body really is 1. A numerical check of the returned finite expression, a comparison of its coefficients against the same body, or an assertion that all displayed coefficients are real will all pass. The regression must inspect whether the \emph{conditional call is admitted}, not just the arithmetic of its selected branch.

Finally, the issue is not repaired by merely retaining the original condition as a text label after computing the result. The ordinary public route claims that the condition has been proved on the input germ. A result with an empty actual domain should not be presented as an ordinary successful asymptotic object whose exactness invites downstream arithmetic. The smallest compatible repair is to refuse an unproved condition in the existing place.

\subsection{The quotient-space obstruction}
It is helpful to state the limitation independently of this particular code. Let \(q_P\) map a function to its finite jet modulo \(\OO(x^P)\). A predicate \(\mathcal P\) can be decided from that jet alone only when the decision is valid for every function consistent with the retained information. Real-valuedness does not descend to this quotient:
\[
 q_P(0)=q_P(\ii x^P),\qquad
 \mathcal P(0)=\text{true},\quad
 \mathcal P(\ii x^P)=\text{false}.
\]
Thus no rearrangement of the retained real coefficients can provide the missing proof. Either exactness or additional semantic evidence about the discarded part is necessary.

This observation also prevents an overcorrection. A nonzero magnitude remainder does \emph{not} prove that an expression is nonreal. Both a real and a nonreal function may share it. The appropriate low-information outcome is ``not proved,'' which the existing public call can express through \code{IncompatibleObservableCondition}. The candidate patch below does not label all finite tails as complex.

\section{A narrow repair and its acceptance criteria}
\subsection{The candidate change}
For the current ordinary-jet convention, the minimal conservative repair is:
\begin{lstlisting}
Return[
  j[[2]] === Infinity &&
  And @@ (TrueQ[FullSimplify[
    Element[#[[2]], Reals],
    seriesAss[d] && Element[d["LogVariable"], Reals]
  ]] & /@ j[[1]]),
  Module]
\end{lstlisting}
It adds one requirement: a coefficient-only realness proof is permitted only for an exact jet. An empty exact jet still proves exact zero and hence realness. An empty finite-precision jet no longer does. Real finite exact polynomials remain admissible when their coefficients are proved real under the retained assumptions.

The patch does not alter \code{seriesJetApply}, change coefficient arithmetic, invent a new remainder type, or change the public failure tag. It does not affect the mathematical meaning of native \code{Element}. The changed rule is solely the package's use of its approximation as evidence.

\subsection{The deliberate conservatism}
The guard is sufficient for this coefficient-only proof rule, but not complete for all real expressions. A non-polynomial expression can be genuinely real on a real input while its truncated jet has a finite remainder. Rejecting such a jet as insufficient \emph{coefficient-only evidence} is conservative. It does not say that the original expression is nonreal.

Consequently the patch is best understood as closing an unsound implication, not as completing real-domain inference. A later extension may establish an individual complete predicate from an exact source expression and the already retained input domain. Such an extension must prove the actual composed argument, not replace it by the finite approximation and reuse the same invalid implication. This report does not propose a second broad real-germ architecture under a new name; those wider obligations already have entries in the existing review register.\cite{register}

The immediate tradeoff is therefore explicit: retain the established exact cases and refuse finite-precision cases that previously succeeded without the required proof. For a correctness-first mathematical API, that is preferable to returning an exact value on an empty domain. A future completeness improvement can restore particular refused cases with a separate proof, without weakening this boundary again.

\subsection{Regression design that targets the mechanism}
The delivered \code{tests/PredicateRealness.wl} uses a small explicit runner and does not depend on MUnit. It expects the false-predicate calls to be refused. The unpatched baseline is therefore expected to fail the corresponding desired-behavior assertions. The complete file contains the exact source control, ten cutoff-pair cases, exact real polynomial controls, an exact nonreal polynomial refusal, and an exact-zero control.

The cutoff-pair construction is more discriminating than a collection of unrelated functions. It deliberately moves the first decisive coefficient across the exclusive cutoff while leaving the underlying condition unchanged. It tests whether the checker confuses ``not visible'' with ``proved absent.'' The exact-zero control prevents a repair from conflating a genuinely zero expression with a pure remainder. The exact polynomial control prevents the easiest but unnecessarily broad workaround of rejecting every \code{Element} condition.

A useful expansion of this same regression family varies the body independently from the predicate: use 1, a real constant, and a supported real polynomial body. Their conditional calls should have the same admission decision. This tests that a harmless body cannot mask an invalid precondition. Such additional cases are a proposed extension of this narrow regression, not recorded executed results.

Do not make the regression depend on a high-precision numerical sample of \(T_m\). Near zero, subtracting a Taylor polynomial from an exponential can suffer cancellation, exactly where the analytic proof is simplest. The positivity series proves the required fact without any numerical tolerance.

\subsection{Patch staging and replay}
The supplied \code{code/patch_predicate.py} reads a checkout but never modifies it. It requires the pinned commit, compares the relevant working modular file with the committed version, refuses a missing or ambiguous source anchor, and refuses reapplication. It writes a modified modular file and a unified diff to a separate, previously nonexistent output directory.

Four independent fixture tests check the transformation itself: the single edit, a missing anchor, duplicate anchors, and an already patched anchor. They do not claim that an entire checkout was staged locally. Network restrictions prevented obtaining a complete local repository, so the staging command's real-checkout path was not executed in this audit. Its purpose is to make the proposed edit reproducible and resistant to accidental application to a different revision.

After reviewing and applying the generated diff in a disposable pinned checkout, regenerate the standalone through the repository's existing builder. That rebuild is necessary because the canonical modular source and the generated public load artifact are different files. No claim is made that editing the modular file alone changes an already downloaded standalone.

\section{Wolfram 15 and Mathics3: what can be concluded}
\subsection{Wolfram 15 evidence}
The native observations use Wolfram 15.0.0 on Linux x86-64. They establish that N01 is not merely a hypothetical concern about an alternate interpreter. A fully loaded public package call exhibits the failure on the primary evaluator. The fixed-anchor experiments also establish that the proposed local guard is syntactically valid there and changes the selected public outcomes as intended.

The observations do not establish behavior on every Wolfram 15 maintenance release or operating system. They also do not establish that unrelated routes are unaffected. The patch is small, but smallness is not a substitute for integration testing; the evidence record deliberately keeps focused observations separate from complete-suite acceptance.

\subsection{Source-level Mathics analysis}
The package isolates compatibility helpers in \code{AsymptoticAnalysis`Mathics`}. The inspected compatibility source supplies private forms for selected operations such as module returns, lookup and key handling, and matching; other modules supply assumptions, numerical, and Taylor support. The main source is parsed under the appropriate compatibility context rather than globally replacing every system definition in the user's session.\cite{mathicscompat,mathicsassumptions,mathicstaylor,mathicsnumerical}

N01 lives above those primitive adapters. Its incorrect implication is expressed in the shared condition-on-jet source: obtain a precision-tracked result, ignore its precision, and conjoin realness claims for the finite rows. The one-line repair uses the already existing ordinary exactness sentinel and standard conditional conjunction. It introduces no new algebraic-number solver, special-function dependency, numerical backend, or unsupported proof command.

That makes the guard a plausible portable change at the source level. It does \emph{not} prove that the identical public witness currently reaches the same branch on Mathics. Evaluation of the conditional expression, assumptions containing \code{a == I}, analytic expansion, and the private realness adapters may differ. A source-level shared defect can be unreachable for a particular input on one interpreter because an earlier operation refuses the input. Such an earlier refusal would not make the defective implication sound; it would change the public coverage of that input.

The appropriate Mathics check is therefore not just to evaluate \code{And@@{}} or import the isolated helper. Load the actual pinned or patched package, evaluate the public source constructor, verify that the exact source and assumptions were retained, and then run the same low/high-cutoff pairs. The test file is provided for precisely that end-to-end route. No Mathics pass/fail result is filled in speculatively.

\subsection{Version and installation boundaries}
At the time of this review, the official PyPI project page lists Mathics3 10.0.1 and a Python requirement of at least 3.11. This identifies a concrete public runtime target; it is not a statement that it was installed locally.\cite{mathicspypi}

The local artifact tests used Python 3.13.5 and only the standard library. They test the independent exact Fourier algebra and the patch transformation. Their success says nothing by itself about Mathics evaluation rules. Conversely, the mathematical proof of the false condition is independent of both interpreters. Keeping those three levels---mathematics, Python model, and native package execution---separate makes the compatibility assessment useful rather than turning unrelated pass counts into a misleading total.

\subsection{A control that did not become a finding}
A separate probe examined whether changing the public default backend to \code{"Series"} could alter refinement of a previously constructed package-only expansion. For the tested \(e^x\) source at cutoff 3, \code{SeriesRefine[s,5]} returned the same analytic forward result under that changed default and after restoring the original options: the expression through \(x^4/24\) and a \code{PowerLogRemainder[x,5,0]}.

This hypothesis was not promoted to a defect. The result is a control for that selected path, not proof that every possible default interaction is correct. Recording such negative outcomes helps distinguish actual review work from a report that presents every source suspicion as a confirmed issue.

\section{H01: a lossless half-spectrum coefficient algebra}
\subsection{The current full-spectrum work}
The Fourier engine represents a coefficient in the logarithmic variable \(L\) as a finite sum
\begin{equation}\label{eq:fourier}
 A(L)=\sum_{\omega\in\Omega} A_\omega(L)e^{\ii\omega L},
 \qquad A_\omega\in\CC[L],\quad\Omega\subset\RR.
\end{equation}
The source-power weights remain separate from these frequencies. The implementation normalizes and merges equal frequencies, multiplies coefficient spectra by a full Cartesian convolution, and applies the Euler derivative to each mode through
\begin{equation}\label{eq:euler}
 \frac{d}{dL}\bigl(A_\omega(L)e^{\ii\omega L}\bigr)
  =\bigl(A_\omega'(L)+\ii\omega A_\omega(L)\bigr)e^{\ii\omega L}.
\end{equation}
The constructor also verifies the conjugacy relations required for a real coefficient. These mechanisms already exist; H01 does not propose to rediscover sparse convolution or Euler differentiation.\cite{fourier}

For an admitted real coefficient, the stored modes satisfy
\begin{equation}\label{eq:hermitian}
 A_{-\omega}(L)=\overline{A_\omega(L)},\qquad A_0(L)\in\RR[L].
\end{equation}
Once this relation is established, storing and multiplying both signed halves is redundant. The alternative representation is
\begin{equation}\label{eq:half}
 A(L)=a_0(L)+2\operatorname{Re}
       \sum_{\alpha>0}a_\alpha(L)e^{\ii\alpha L}.
\end{equation}
Only the zero polynomial and positive-frequency polynomials are stored. Negative-frequency information is reconstructed by conjugation; no frequency has been discarded and no approximation has been introduced.

This is a finite Fourier-polynomial representation, not an FFT grid. The frequencies need not be integers, rationally commensurate, or periodic with a shared finite period. The algorithm needs exact addition, subtraction, equality, and sign decisions for frequencies, just as the original exact-frequency algebra does.

\subsection{Admission must precede compression}
The half representation cannot be used as an excuse to accept arbitrary nonreal input. Given a full spectrum, first perform the existing normalization and real-conjugacy checks. Only then retain its nonnegative half. Simply taking the positive rows of an arbitrary spectrum and declaring the negative rows to be their conjugates would change the represented function.

For example, the single full mode \(e^{\ii L}\) is not the real coefficient \(2\cos L\). Compressing it without an admission check and reconstructing a reflected negative mode would silently perform exactly that change. The independent prototype's \code{from_full} method rejects non-Hermitian input; the zero mode is separately required to have real polynomial coefficients.

Equal-frequency grouping remains indispensable. A frequency can be zero by exact algebraic equality even when its input expression is not syntactically zero. Production compression must use the package's established exact canonicalization and ordering conventions, not a floating-point comparison or string sign test. The prototype makes this obligation explicit by restricting frequencies to a small exact field rather than claiming to replace the package's arbitrary exact-real support.

\subsection{Half-spectrum multiplication}
Write
\begin{align*}
 A &= a_0+\sum_{\alpha>0}
       \left(a_\alpha e^{\ii\alpha L}
       +\overline{a_\alpha}e^{-\ii\alpha L}\right),\\
 B &= b_0+\sum_{\beta>0}
       \left(b_\beta e^{\ii\beta L}
       +\overline{b_\beta}e^{-\ii\beta L}\right).
\end{align*}
The zero/positive interactions are straightforward: \(a_0b_0\) contributes to zero; \(a_0b_\beta\) and \(a_\alpha b_0\) contribute to their positive frequencies. Their reflected partners need not be computed separately.

For each positive pair \((\alpha,\beta)\), compute only
\begin{equation}\label{eq:twoproducts}
 S=a_\alpha b_\beta,\qquad
 C=a_\alpha\overline{b_\beta}.
\end{equation}
Add \(S\) at \(\alpha+\beta\). For the difference mode, use
\begin{equation}\label{eq:difference}
\begin{cases}
 C \text{ at } \alpha-\beta, & \alpha>\beta,\\
 \overline C \text{ at } \beta-\alpha, & \alpha<\beta,\\
 C+\overline C \text{ at }0, & \alpha=\beta.
\end{cases}
\end{equation}
All contributions landing at the same frequency are added exactly, and identically zero polynomials are removed after collection.

\begin{proposition}
Equations~\eqref{eq:twoproducts}--\eqref{eq:difference}, together with the zero/positive interactions, produce exactly the nonnegative half of the full Cartesian product of two Hermitian Fourier-polynomial spectra.
\end{proposition}
\begin{proof}
Each positive pair supplies four signed products in the full expansion. The positive-positive product is \(S\) at \(\alpha+\beta\), and the negative-negative product is its conjugate at the opposite frequency. The positive-negative product is \(C\) at \(\alpha-\beta\); the negative-positive product is its conjugate at \(\beta-\alpha\). For nonzero difference, exactly one belongs in the positive half. For zero difference, the two terms coincide in frequency and add to the real polynomial \(C+\overline C\). The zero-mode interactions have the same conjugate pairing because \(a_0,b_0\) are real. Exhausting these cases exhausts the Cartesian product.
\end{proof}

A negative difference must be reflected \emph{and conjugated}. Reflecting its frequency alone is a subtle wrong implementation: it generally reverses the sign of the sine component. Likewise, the equal-frequency case needs \(C+\overline C\), not just \(C\), and the zero mode must not be doubled a second time at presentation.

\subsection{Elementary identities that test the difficult cases}
The identity
\[
 \sin L\sin 2L=\tfrac12\cos L-\tfrac12\cos3L
\]
exercises a negative difference. In the half representation, the output coefficients are \(1/4\) at frequency 1 and \(-1/4\) at frequency 3. The factor of two in~\eqref{eq:half} converts them to the displayed cosine coefficients.

Similarly,
\[
 \sin^2L=\tfrac12-\tfrac12\cos2L
\]
exercises a collision at zero: the half spectrum contains the real zero coefficient \(1/2\) and positive frequency-2 coefficient \(-1/4\). Both identities are exact tests in the supplied prototype. They supplement, rather than replace, the larger Cartesian-oracle tests.

\subsection{Closure under Euler differentiation}
For a stored positive mode, apply \(D_L+\ii\omega\) to its polynomial. The reflected mode transforms as
\[
 (D_L-\ii\omega)\overline{A_\omega}
   =\overline{(D_L+\ii\omega)A_\omega}.
\]
Thus Euler differentiation preserves the Hermitian relation. The zero polynomial's derivative remains real. Addition, multiplication, and scaling by a proved real scalar preserve it as well. Integer powers can therefore use the existing binary-powering strategy entirely within the half representation.

This closure is particularly well suited to the repository's inverse-coefficient recurrence. There is no need to expand to a full signed spectrum after every derivative or real scalar shift. The boundary conversion can be delayed until a public expression, mode list, or independent full-spectrum comparison is requested. Whether that delayed conversion yields a useful end-to-end speedup still needs measurement.

\subsection{Compatibility with the existing inverse recurrence}
For one perturbation, consider the normalized source model
\begin{equation}\label{eq:sourcefourier}
 y=u^p\left(1+\varepsilon u^\delta B(\log u)\right),
 \qquad p\ne0,\quad\delta>0.
\end{equation}
The marker \(\varepsilon\) organizes the coefficient calculation. With \(z=y^{1/p}\), the observable \(u^r\) has coefficients of \(z^{r+n\delta}\) given by the existing Euler form
\begin{equation}\label{eq:lagrange}
 C_n(L)=\frac{(-1)^n r}{p^n n!}
   \prod_{j=1}^{n-1}
   \left(D_L+r+n\delta+pj\right)B(L)^n,
 \qquad n\ge1,
\end{equation}
and \(C_0=1\). This is the one-perturbation specialization of the coefficient construction already present in the Fourier module.\cite{fourier}

For completeness, it follows by setting \(v=u^p\), so the implicit equation becomes
\[
 y=v+\varepsilon v^{1+\delta/p}B(\log v/p).
\]
The Lagrange coefficient for \(v^{r/p}\) is
\[
 \frac{(-1)^n}{n!}\left(\frac{d}{dy}\right)^{n-1}
 \left[\frac rp\,y^{(r+n\delta)/p+n-1}
 B(\log y/p)^n\right].
\]
Each derivative supplies a factor \(p^{-1}\) times an Euler operator; collecting the powers of \(y\) gives~\eqref{eq:lagrange}. This derivation is used here to verify representation closure, not to claim a new inverse algorithm.

Every scalar shift in~\eqref{eq:lagrange} is real under the admitted real source data. H01 therefore implements the same recurrence without constructing conjugate duplicate polynomial products. For \(p=r=\delta=1\), the first two corrections are
\[
 C_1=-B,\qquad C_2=2B^2+BB'.
\]
For example, \(B(L)=(1+L)\sin L\) gives
\[
 u=y-y^2B(\log y)
   +y^3\bigl(2B^2+BB'\bigr)(\log y)+\cdots.
\]
The prototype tests these low-order identities and compares four higher recurrence depths with a separate full-spectrum implementation. No new convergence theorem or remainder improvement is inferred from changing the coefficient storage.

\section{Exact work counts, prototype scope, and integration}
\subsection{What is saved, and what is not yet measured}
Let \(m_A,m_B\) be the counts of nonzero positive modes. Let \(z_A,z_B\in\{0,1\}\) indicate whether a nonzero zero mode is present. A direct full-spectrum convolution performs
\begin{equation}\label{eq:fullcost}
 F=(2m_A+z_A)(2m_B+z_B)
\end{equation}
polynomial multiplications before collection. The half algorithm performs
\begin{equation}\label{eq:halfcost}
 H=2m_A m_B+z_A m_B+z_B m_A+z_Az_B.
\end{equation}
Hence
\[
 F-H=2m_A m_B+z_A m_B+z_B m_A.
\]
Without zero modes, the count is exactly halved. With zero modes, the shared zero-zero product is not duplicated in either algorithm.

The delivered test uses \(m_A=2,m_B=3,z_A=z_B=1\). Its exact result is identical under both implementations, while the polynomial-product counters are
\[
 F=35,\qquad H=18.
\]
This is a reduction in a precisely defined operation count for a matched input, \emph{not} a claim of a \(35/18\) wall-time speedup in Wolfram or Mathics. Polynomial sizes, conjugation, frequency normalization, symbolic assumptions, collection, and public materialization all contribute to actual time. A scalar count also does not describe peak memory or interpreter allocation behavior.

The half representation stores \(m_A+z_A\) polynomial entries instead of \(2m_A+z_A\). That is a statement about representation cardinality, not a measured object-byte reduction. A public API that returns the full signed spectrum still produces the same final number of public entries.

\subsection{Preserve the meaning of resource limits}
The existing Fourier code treats \code{MaxFrequencies} as a hard budget on exact frequencies, not as permission to truncate modes. It also bounds candidate Cartesian products through \code{MaxTerms}. A storage optimization must not silently reinterpret either option.\cite{fourier}

For initial integration, retain the old full signed-frequency count
\[
 N_{\rm public}=2m+z
\]
when checking or reporting the frequency budget. Likewise, a compatibility mode can check the virtual full pair count~\eqref{eq:fullcost} before running the half convolution. That preserves the old preflight decision even though fewer polynomial products are actually executed.

This may appear to leave some performance headroom inaccessible under the old budget, but it cleanly separates two changes: lossless representation optimization and API policy. A later explicit policy may permit the cheaper implementation to handle larger jobs under a redefined work budget. Such a policy change should be visible and tested, not hidden inside a conjugacy optimization.

Stage ordering also matters. A product that exceeds the legacy candidate-pair budget must not start expensive new work merely because its final merged support would be small. Conversely, cancellations at the final merge should still remove frequencies before applying the merged-frequency check where the current code does so. Matching final coefficients alone is insufficient when a public option controls refusal behavior.

\subsection{The independent exact implementation}
The delivered \code{code/hermitian_fourier.py} is an independent standard-library implementation. Frequencies lie in
\[
 K=\QQ(\sqrt2),
\]
and polynomial coefficients lie in \(K[\ii]\). Exact field elements are stored as rational pairs \(a+b\sqrt2\); complex coefficients are pairs of such elements. Polynomial coefficients are immutable tuples. Spectrum maps are normalized by exact addition, and zero polynomial entries are removed.

The restricted field was chosen to exercise non-rational frequencies without depending on a symbolic simplifier. For opposite-sign \(a\) and \(b\), the sign of \(a+b\sqrt2\) is decided by comparing \(a^2\) and \(2b^2\), after the competing magnitudes have been made positive. No floating-point approximation is used for ordering or equality. Values such as \(2-\sqrt2\), \(\sqrt2\), and \(1+\sqrt2\) produce both difference signs and exact collisions during convolution.

This restriction is also an explicit limitation. The prototype does not implement arbitrary exact-real frequencies, symbolic parameter assumptions, native Wolfram expression normalization, package resource accounting, public result objects, source-weight truncation, or error contracts. It is an exact coefficient-algebra experiment, not a drop-in package replacement. Its \code{lagrange_single} routine covers one perturbation; the package's multi-index frontiers remain outside this artifact.

The reference implementation uses a genuinely different schedule: expand both spectra and take the ordinary full Cartesian product. It shares primitive exact polynomial operations with the optimized implementation but not the half-spectrum routing logic. Equality against this reference therefore checks the most error-prone part of H01: which product is placed at which signed or zero frequency.

\subsection{Executed test populations}
The Fourier prototype has eight executed test methods. Within those methods, 80 deterministic randomized cases compare half multiplication against full Cartesian convolution, 12 cases check Euler differentiation and the Leibniz rule, and four recurrence depths compare the half and full coefficient constructions. Additional methods check exact field ordering, admission failures, trigonometric identities, low-order inverse coefficients, and the 35-versus-18 work count.

Four separate methods test the patch transformation on small string fixtures. The combined Python run reports \textbf{12 methods passed}, with no failures. The saved run used Python 3.13.5 and completed in 0.886 seconds. That duration is a test-run observation in this environment, not a package benchmark and not an expected runtime guarantee for another machine.

The distinction between methods and subcases is deliberate. The 80, 12, and four subcase populations are not added to native observations or to upstream test counts. No Mathics tests are hidden inside these figures. The earlier Fourier-only log is retained alongside the combined log so the progression of local checks is visible.

\subsection{A concrete integration sequence}
The first implementation boundary should be private to \code{FourierCoefficients.wl}. Keep the public coefficient and result schema unchanged. Convert an already normalized, already admitted real full spectrum to a private half spectrum; implement the sum/difference convolution and Euler transform there; materialize the full mode list at existing public boundaries. This avoids using a broader representation refactor as a prerequisite for testing the specific optimization.

The first native comparison should run the old and new coefficient paths on identical admitted inputs and compare the normalized full modes exactly. It should include positive/negative frequency differences, zero collisions, algebraic resonances, polynomial cancellation, zero-mode-only inputs, and nonreal input refusals. The existing public \code{FourierInverseResidual} route can supply an additional integration check after the coefficient comparison, but it should not be the only oracle: a construction and its checker can share assumptions and code.

Only after exact output and budget behavior agree should timing or allocation measurements guide a decision. Matched cases must return the same coefficients and preserve the same source-weight and remainder metadata. A faster call that silently changes frequency accounting, omits modes, or weakens the result is not the proposed optimization. The independent prototype demonstrates correctness of the algebraic schedule; it does not settle whether native conjugation and canonicalization costs make the optimization worthwhile for the repository's actual workloads.

\section{Recommended decisions}
The correctness and performance work should remain separate changes. For N01, the immediate decision is whether to accept the conservative exactness guard, followed by the distributed desired-behavior regressions on the actual modular rebuild and both intended evaluators. Its public failure tag can remain unchanged. The one-line repair should not be delayed until a complete semantic realness system is designed.

For H01, the immediate decision is whether a private half-spectrum experiment is worth integrating behind the existing full-spectrum boundary. The exact Python model provides a reproducible reference and a precise cost hypothesis. Native measurements should determine whether to keep it. There is no justification here for promising a fixed speedup, changing the frequency cap, or replacing exact real comparisons with numerical ones.

The most useful additional predicate work is narrowly targeted: extend the Taylor-tail family, vary the harmless observable body, and explicitly distinguish exact zero from a zero finite prefix. That directly attacks the demonstrated implication. The most useful additional Fourier work is similarly concrete: retain Hermitian admission, test zero/difference routing, and preserve legacy budget units while measuring the alternative representation.

The wider repository remains a substantial collection of interacting analytic representations and compatibility adapters. This review does not convert its selected controls into a claim that all remaining paths are correct, nor does it restate already registered work as new obligations. Its deliverable is a reproducible incremental result: one specific unsound public admission rule with a tested local repair, and one exact lossless coefficient optimization with enough mathematics and code to evaluate it independently.
