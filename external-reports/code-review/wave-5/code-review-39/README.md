## Reproduce independent checks

Use Python 3.10 or later with pytest installed. From this directory:

```sh
python -m pytest -q tests
python code/generate_evidence.py
```

The saved run has **34 passing pytest cases**. These include an independent exact
rational/dyadic interval model, synthetic validator records, and source-patcher
fixtures. They are not package acceptance tests. `independent-results.json` is
regenerated by the second command. Its numbers are operation counts, not timing
benchmarks. Synthetic fingerprints inside validator fixtures are dummy data, not
fingerprints of the repository.

## Candidate fixes

`apply_truncation_fix.py` prints a source-matched diff by default:

```sh
python code/apply_truncation_fix.py /path/to/checkout
python code/apply_truncation_fix.py /path/to/checkout --write
```

The second command is opt-in and changes only `src/Kernel/SeriesOperations.wl`.
It refuses an unmatched or already modified key list. Rebuild the standalone file
with the repository's `python validation/build_standalone.py`, then run focused
native tests. No production patch acceptance is claimed in this bundle.

`receipt_guard.py` is a candidate preflight guard around the copied upstream shard
validator. It preserves the existing entry-filename check and adds selected-entry
membership in the fingerprint map and absence of a recorded first source mismatch. Lexical
path normalization is not filesystem identity or proof of what actually executed.

`affine_model.py` is an independent prototype, not a replacement for the Wolfram
certificate engine. It demonstrates request-local classification reuse while
preserving the old interval endpoints on its bounded grammar.
